Hán-Việt Reading Research

Sino-Vietnamese Coverage Analysis

§1

The Problem

SINO-CONV uses Unicode's Unihan database (via dahlia/unihan-json, Unicode 12.1.0) as its source for character-level pronunciation readings. The kVietnamese field provides Sino-Vietnamese (Hán-Việt) readings — but its coverage is far behind the other four languages.

Coverage Comparison

Field Language Entries Coverage
kMandarin Pīnyīn (Mandarin) 71,111 Broadest — covers nearly all CJK
kJapaneseOn On'yomi (Japanese) 13,175 Good — common Kanji well covered
kHangul Hangul (Korean) 8,411 Decent
kVietnamese Hán-Việt (Vietnamese) 8,300 Weakest — many common chars missing

Vietnamese has roughly 11.7% the coverage of Mandarin, and even trails Korean by ~100 entries. Characters that any Vietnamese speaker would know the Hán-Việt reading for are simply absent.

§2

The Nôm vs Hán-Việt Discovery

After forking KanjiDictVN (10,383 entries from hvdic.thivien.net) and cross-referencing against Unihan, a critical finding emerged:

Unihan’s kVietnamese field stores Nôm / colloquial Vietnamese readings, not Sino-Vietnamese (Hán-Việt) readings. KanjiDictVN stores proper Hán-Việt. These are fundamentally different reading layers of the same characters.

For SINO-CONV’s purpose — showing how Chinese characters are read in Vietnamese scholarly tradition — Hán-Việt is what we want. The Nôm readings are valuable for a different purpose (Chữ Nôm decipherment), but for a CJKV converter, Hán-Việt is the correct parallel to on’yomi (Japanese), hangul readings (Korean), and pīnyīn (Mandarin).

§3

The Dị Thể / Biến Thể Gap

Some missing entries follow a pattern: Unihan maps the traditional form but not its simplified or shinjitai variant. These are dị thể (異體 — variant forms) or biến thể (變體 — transformed forms) — characters where Japan or China reformed the glyph but the meaning and pronunciation are identical.

TraditionalkVietnameseVariantkVietnameseRelationship
變 U+8B8A biến ✓ 変 U+5909 MISSING ✗ JP shinjitai
變 U+8B8A biến ✓ 变 U+53D8 MISSING ✗ CN simplified
學 U+5B78 học ✓ 学 U+5B66 ? JP shinjitai / CN simplified

Strategy: Cross-reference variant chains. If a simplified or shinjitai character has no kVietnamese entry, but its traditional source form does — we can confidently inherit the reading. OpenCC already maps these relationships. The reading didn’t change when the glyph was reformed — only the strokes did.

Accuracy estimate pending — need to measure how many gaps this fills and what percentage are clean 1:1 mappings vs. split readings.

§4

The Cantonese–Vietnamese Correlation

It is widely observed (though hard to pin to a single academic source) that Cantonese (Quảng Ðông) pronunciations are strikingly close to modern Hán-Việt readings — often more so than Mandarin. This is because both Cantonese and Vietnamese Hán-Việt readings descended from Middle Chinese, preserving final consonants (-p, -t, -k, -m, -n, -ng) and tonal distinctions that Mandarin has merged.

Strategy: Cantonese as a bridge. Unihan’s kCantonese field has far better coverage than kVietnamese. For common glyphs that have a Cantonese reading but no Vietnamese one, the Cantonese pronunciation can serve as a phonetic guide to predict or verify the missing Hán-Việt reading — especially for characters with regular sound correspondences.

This is a secondary fallback — thivien.net data is preferred when available. Cantonese bridging helps for cross-verification and confidence scoring.

§5

Data Sources

Primary: hvdic.thivien.net

The most comprehensive Sino-Vietnamese dictionary available online, with approximately 400,000+ entries covering Hán-Việt, Chữ Nôm, and compound words. Provides a JSON API:

POST https://hvdic.thivien.net/transcript-query.json.php
Content-Type: application/x-www-form-urlencoded

mode=trans&lang=1&query=韓換変

Parameters: mode=trans, lang=1 (Sino-Vietnamese), lang=2 (Pinyin), lang=3 (Nôm).

Secondary: KanjiDictVN

trungnt2910/KanjiDictVN — MIT-licensed project that already scraped thivien.net to build a Yomitan-compatible dictionary with ~10,350 entries. Pre-extracted data that can serve as a starting point.

Baseline: Unihan kVietnamese

Unicode Consortium’s official data. 8,306 entries as of Unicode 17.0.0. Reliable where present, but incomplete. Our current readings.js is built from this via build_readings.py.

Known errors in thivien.net. User comments on the site report mistakes. The database likely predates machine-learning-era quality control. Any forked data must be scanned and cross-verified before merging.

§6

Plan

Phase 1 — Fork & Merge

  • Fork KanjiDictVN data (~10,350 chars) as baseline expansion
  • Query thivien.net API for CJK Unified Ideographs range (U+4E00–U+9FFF, ~21K chars)
  • Merge with existing Unihan kVietnamese data, preferring Unihan where both exist
  • Store merged data locally in research/data/

Phase 2 — Error Scan

  • Cross-verify thivien.net readings against Unihan where overlapping
  • Flag discrepancies for manual review
  • Focus on common characters (HSK lists, JLPT kanji, frequent-use tables)
  • Side-by-side comparison tables published here

Phase 3 — Variant Auto-fill

  • Map simplified → traditional → kVietnamese via OpenCC conversion tables
  • Map shinjitai → kyūjitai → kVietnamese
  • Calculate accuracy rate: what % of variant→traditional mappings are clean 1:1 reading inheritance
  • Auto-fill only where confidence is high; flag ambiguous cases

Phase 4 — Cantonese Bridge

  • For remaining gaps: use Unihan kCantonese as phonetic predictor
  • Build Cantonese→Hán-Việt correspondence table from known pairs
  • Predict missing readings with confidence scores
  • Manual verification for predicted entries

Scope

Goal: Full Hán-Việt coverage for all common modern Simplified and Traditional Chinese characters, plus common Japanese kanji. We are not aiming to cover all obsolete glyphs or the full Chữ Nôm repertoire — that is beyond SINO-CONV’s current scope.
